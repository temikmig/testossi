# Статусы ноутбука на складе

Тестовое задание: функция смены статуса ноутбука на TypeScript и тесты к ней.

## План

1. Типы: статусы, ноутбук, запись истории.
2. Допустимые переходы задать мапой: статус -> список статусов.
3. Функция changeStatus: проверить переход, отдельно случай возврата (14 дней), записать в историю.
4. Тесты: все разрешенные переходы, все запрещенные, границы возврата.
5. Дописать в README ответы на вопросы.

## Как запустить

```bash
npm install
npm test
npm run typecheck
```

## Что было непонятно и как решил

1. "Не позднее 14 дней" - включительно или нет? Решил что включительно, 14-й день еще
   проходит. У AI стояло `>=`, то есть этот день отсекался. Поправил и закрыл тестами
   с двух сторон: ровно 14 дней и 14 дней плюс миллисекунда. Заодно дату перехода вынес
   в третий аргумент, иначе границу не проверить без моков таймера.

2. В задании "возвращает понятную ошибку", а не "кидает". Кидаю: после неудачной смены
   статуса продолжать все равно нельзя, а молча пропустить возвращенное значение слишком легко.

3. Откуда брать дату продажи для отсчета? Из истории, последний переход в "Продан".
   Если статус "Продан", а история пустая, возврат запрещаю - отсчитывать не от чего.
   У AI там стоял `!`, код падал с TypeError.

## Какие запросы давал AI

1. Текст задания целиком плюс: "напиши на TypeScript типы и функцию changeStatus, переходы
   задай мапой статус -> список статусов, ошибка с полями from/to и понятным сообщением".
2. "Напиши тесты на vitest: все допустимые переходы, все недопустимые включая переходы
   из Списан, запись в историю, возврат в пределах и позже 14 дней".

Дальше правил сам: граница 14 дней, падение на возврате без даты продажи, класс ошибки
переписал на фабрику.
